# Landing Check 演示视频脚本 · v1

目标时长 100 秒左右。一条主线：Alex 落地上海的第一小时。
每一幕右上角打一个小角标，把评审要看的链路钉出来：
**Trip data → Context → Diagnosis → AI reasoning → Knowledge → Action**

默认假设（可改，见文末问题）：
- 界面全英文（产品本来就是给外国散客的），旁白中文，关键句叠英文字幕。
- 真机录屏 `h5/?api=...` 接 Render 后端，穿插 2 到 3 个实拍空镜（机舱、到达厅、出租车）。
- 人物：Alex，美国人，第一次来中国。航班 UA 857 SFO → PVG T2（模拟数据里现在是 CX 362 HKG → PVG，国籍 GB，需要改）。

## 录前准备

1. Render 先打开一次 `/health` 唤醒，确认 `kb_scenarios` 四个场景都在。
2. `POST /mock/reset`，把 `backend/mock/trip.json` 改成美国直飞（见问题 3）。
3. 行前检查：eSIM 标 bought=true，支付不验证，这样落地卡才是 Internet ✓ / Payment ⚠。
4. `POST /mock/flight/land` 触发落地卡。
5. 在 `/test` 页用选定的绑卡失败截图跑一遍，确认命中 `alipay_card_bind_failed`，置信度在 answer 档。
6. 录屏用 iPhone 原生录屏，393 宽设计稿在 iPhone 15/16 上一比一。

## 需要你拍板的问题

1. **时长**：现在按 100 秒写。初赛要求几分钟？要 2 到 3 分钟的话我把每一幕的旁白展开，加一段 15 秒的"为什么是 Trip.com 能做"（1 元验证走 Trip.com 收款通道、接机在行前订）。
2. **旁白语言**：中文旁白 + 英文界面 + 双语字幕；还是全英文（更像面向用户的产品片）？
3. **人物设定**：模拟数据现在是英国人、香港飞上海。要不要我改成美国人、UA 857 SFO → PVG，和故事一致？
4. **第 3 幕的失败场景**：用"绑卡失败"（知识库有现成条目，识别命中率高），还是"柜台付款被拒"？你写的三条建议对应的是绑卡失败。
5. **录制形式**：真机录屏 + 实拍空镜；还是全部用导出图做动效（省事，但少了"真的能跑"的说服力）？我建议前者，I'm stuck 那一步一定要真实调后端。
6. **要不要露技术画面**：比如 3d 旁边切 1 秒后端返回的 JSON（entry id、confidence、mode），给评审看"模型只选条目 id，不生成答案"。会打断故事，但很对评审胃口。
